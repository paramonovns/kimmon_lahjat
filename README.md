# Подарки для Киммо на рождество

Небольшой семейный сайт: Vite+, TypeScript, GitHub Pages и общие резервы в Supabase. Девять подарков с фотографиями и поиском в Google. Контейнер ограничен 1400 px, каждая строка имеет высоту 250 px, включая мобильные экраны.

## Запуск

Требуются Node.js 22.20+ и установленный [Vite+](https://www.viteplus.dev/guide/).

```sh
npm ci
npm run dev
```

Адрес разработки: http://127.0.0.1:5173. Без настроек Supabase можно просмотреть сайт; кнопки резервирования отключены, чтобы не создавать ложные локальные резервы.

## Общие резервы

1. В выбранном Supabase-проекте выполните `supabase/setup.sql` один раз через SQL Editor. Скрипт создаёт изолированную таблицу и небольшой RPC API.
2. Скопируйте `.env.example` в `.env.local` и укажите URL проекта и **publishable** API key. Никогда не используйте `service_role` или secret key.
3. Перезапустите сервер разработки.

Посетитель получает случайный 256-битный ключ, который сохраняется в localStorage. База хранит только его SHA-256-хеш. Публичный API возвращает номер подарка и признаки «занят» / «мой», без ключей, хешей и личных данных. Саму таблицу посетители читать и изменять не могут. Пароли, регистрация и изменение Supabase Auth не нужны.

Резерв атомарный: один подарок может принадлежать только одному посетителю. Повторный запрос владельца безопасен, чужой резерв снять нельзя. Другие открытые страницы обновляются каждые четыре секунды и при возвращении на вкладку. При недоступности сервера новые резервы блокируются до восстановления связи.

Владелец продолжает видеть товар и может снять резерв. Для других строка полностью закрыта подарочной упаковкой, а её содержимое исключено из клавиатурной навигации. Это визуальный сюрприз: каталог статический и доступен в исходном коде сайта.

Ключ привязан к браузеру и адресу сайта. Если очистить данные сайта, открыть приватный режим или другое устройство, управление старым резервом будет недоступно. Если это случилось, владелец проекта может удалить нужную строку из `kimmo_private.reservations_2026` в Supabase SQL Editor.

## GitHub Pages

Репозиторий: https://github.com/paramonovns/kimmon_lahjat

1. В Settings → Pages выберите **GitHub Actions**.
2. В Settings → Secrets and variables → Actions → **Variables** создайте:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY`
3. Отправьте изменения в ветку `main`. Workflow `.github/workflows/deploy.yml` собирает сайт и публикует `dist/`.

Путь `base: './'` поддерживает размещение в подпапке `/kimmon_lahjat/`. Настройки API публичны по назначению; данные защищены правилами БД и серверной проверкой владения.

## Проверки

```sh
npm run check
npm run build
npm run test:db
npx playwright install chromium
npm test
```

Тесты PostgreSQL используют PGlite в памяти и проверяют настоящий SQL: конфликт двух владельцев, снятие своего резерва, невозможность снять чужой, закрытые данные, повторные запросы и неверные параметры. Браузерные тесты проверяют две независимые сессии, перезагрузку, сетевой сбой и размеры 1440, 768, 390 и 320 px. Для UI-тестов API заменён контролируемым тестовым сервером.

## Изменение подарков

Тексты, исходные названия, поисковые запросы и ссылки на источники — в `src/gifts.ts`; фотографии — в `public/images/`. Изображения хранятся локально, поэтому сайт не зависит от доступности магазинных CDN при просмотре. Список использует постоянные ID 7–15 из исходного письма. Для изменения количества или ID необходимо согласованно обновить API и проверку ответа в `src/reservations.ts`.

Точные фото подобраны для LEGO 10478, BABY born 837993 и Play-Doh G2309. Варианты без артикула отмечены словом «Пример». Play-Doh Slime выбран в версии Neon Orange F5989 с маркировкой 3+; другие варианты этой линейки могут иметь другой рекомендуемый возраст.

Источники фотографий перечислены в `public/images/SOURCES.md`.
